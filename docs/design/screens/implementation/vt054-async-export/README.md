# VT-054 browser QA

Verified artifacts are in `direct/`: 8 RUNNING captures (375×812, 768×1024, 1280×800, 1440×900; light/dark) and desktop completion. Codex inspected all 9 images. The existing settings layout, tokens and controls are retained; progress text is visible, controls disabled during work, and no page-level horizontal overflow was observed. Mobile/short viewport uses the existing content scroller, so the bottom of neighboring Danger Zone is outside the visible area; the export action/status itself fits.

The browser used Chromium 151.0.7922.34 and the production frontend bundle, real JWT REST and Socket.IO on local test port 3009, and disposable PostgreSQL. Each combination starts its own job with a controlled generator latch, observes RUNNING before capturing, releases work, and validates the actual downloaded JSON's Board ID and filename. This is local browser evidence, not production deployment or physical mobile device testing. It does not prove assistive-technology behavior or exhaustive contrast compliance.

Earlier attempts forwarded only REST to an ephemeral test server while Socket.IO still used an unavailable default server. Existing realtime protection cleared access snapshots, so the client correctly refused publication despite server completion. A further early mistake resized the page mid-operation, which can remount responsive layout and abort the operation. Those attempts are failures, preserved in assignment logs and `harness-failure.png`; they are not counted as successful screenshots. The final harness uses a production build with `VITE_API_BASE_URL=http://127.0.0.1:3009/api`, matching REST/socket origin and explicit test CORS. No application security rule was weakened to pass.
