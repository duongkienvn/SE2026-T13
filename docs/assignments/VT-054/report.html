Vấn đề

Ở baseline, tải Board JSON/CSV giữ request mở trong khi server tạo snapshot. Người dùng chỉ thấy thông báo chuẩn bị file và khó biết yêu cầu trước đã được nhận hay chưa khi kết nối gián đoạn. VT-054 tách việc tạo snapshot sang job, hiển thị trạng thái và bảo vệ thao tác lặp.

Specification · Kế hoạch AI

Hợp đồng và quyền truy cập

  1. AC1. OWNER gửi format và key UUID v4. POST trả 202 và job ID trước completion. Replay cùng key/payload nhận lại ID. Payload khác trả 409.
  2. AC2. Người tạo job có quyền hiện tại xem PENDING, RUNNING, COMPLETED, FAILED. RUNNING không có phần trăm. COMPLETED có progress 100 và FAILED có mã lỗi an toàn.
  3. AC3. File JSON/CSV chỉ được trả sau completion và kiểm tra lại OWNER/session. Job hết hạn không trả bytes. API export đồng bộ vẫn dùng được.
  4. AC4. Retry FAILED giữ ID, giới hạn 3 attempt. Worker nhận job bằng row lock và lease. Token lease ngăn worker cũ ghi đè kết quả.
  5. AC5. UI hiển thị pha chờ, chạy, tải và lỗi. Retry giữ key trong cùng thao tác. Đổi session hoặc unmount hủy polling.
Invariant. UNIQUE(user_id, idempotency_key) bảo đảm một ID cho một thao tác. Chỉ lease hiện hành mới có thể công bố kết quả. Export là read-only, nên oracle side effect đếm hàng job, attempt và kết quả.

Ràng buộc. Đo 120 tác vụ với p95 ≤ 3500 ms, tách acknowledgement khỏi completion. Dữ liệu job tồn tại qua restart, file tối đa 20 MiB, hết hạn sau 15 phút và bị xóa khi tài khoản được xóa.

Performance · 120 tác vụ đồng thời

Acknowledgement đạt, completion còn chậm

Windows, Node v22.23.4, Intel i5-1340P 16 logical CPU, RAM khoảng 16 GB. PostgreSQL 16 disposable, pool 10, worker 4. Sau 5 warm-up, gửi 120 logical operations với 2 POST cùng key cho mỗi operation. Client poll mỗi giây và kiểm tra bytes JSON. HTTP Agent tái sử dụng tối đa 32 socket. Đồng hồ chạy từ trước lúc request vào hàng đợi socket.
