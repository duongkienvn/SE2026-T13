# Backend foundation gap analysis

Reference: [VN Dev Team NestJS boilerplate](https://github.com/vndevteam/nestjs-boilerplate), reviewed at commit `cb6bea3`. The `EXISTS`, `INCOMPLETE`, and `MISSING` labels describe Kanban **before** this task. `ADAPT` and `DEFER` record implementation decisions. A matching filename alone was not considered complete: behavior, integration, typing, and tests were checked. The comparison covers the reference source tree, test tree, configuration, developer tooling, Docker, CI, and documentation.

CI now runs the existing quality gates and the database integration script against its own PostgreSQL service. The script creates and drops a random test database rather than resetting the service's default database.

The global HTTP limiter uses `HttpThrottlerGuard`, a thin adapter over `ThrottlerGuard` that skips non-HTTP contexts so future Socket.IO gateways do not inherit HTTP IP tracking.

The reference implementation is a design input, not a source of truth for Kanban behavior. Its Active Record base entity, permissive boolean/number conversion, raw SQL parameter logging, and cursor pagination without a unique tie breaker were intentionally not copied. The database schema source of truth remains [database-design.md](database-design.md).
